## 7. 模块专项建议

### 7.1 风格写作（P3）

- **成本**：单次生成最坏 3 次 LLM + 3 次 embedding；应监控 P95 费用
- **体验**：流式首 token ≤ 3s 仍为 taps 未验收项，需真实 Key 联调
- **优化**：重试策略可考虑「仅 deai 失败重试、相似度失败调 prompt 而非全文重写」

### 7.2 聊天助手（P4）

- **Bug**：路由复用导致 session 串线（P0-E01）
- **成本**：建议合并为 1 次 LLM 返回 3 条 JSON 建议
- **质量**：5 会话人工抽检仍为 ◐，需 dev 环境 + 真实模型

### 7.3 文案检索（P5）

- **模型**：ONNX 未就绪时全走 LLM，成本与延迟高；优先完成 Step 5.1
- **任务**：Celery worker 必须运行，否则提交后永久 pending
- **数据**：2 万字 `raw_text` 存读开销大，历史列表应只返回摘要

### 7.4 AI 接入层（P2 核心）

当前标准接法（保持）：

```
业务 Service → PromptEngine.render → LLMGateway.complete/stream → Provider
```

扩展新厂商时**只改 Provider + 环境变量**，业务层不动。

## 8. 推荐实施顺序

```
第 1 周（P0）
  ├─ 生产 settings / secrets / CORS / Swagger
  ├─ DRF 限流 + LLM fail-closed
  ├─ 前端路由 Bug + 登录错误 + 登出清缓存
  └─ WS 鉴权方案设计

第 2–3 周（P1 性能/成本）
  ├─ Element Plus 按需加载
  ├─ DB 复合索引 + prompt 缓存
  ├─ LLM stream 日志 + 聊天建议合并
  └─ Celery 事务 + 重试

第 4 周（P1 质量）
  ├─ users/tasks 测试 + CI lint
  ├─ requirements/package 锁版本
  └─ 公共 upload / 禁止词抽取

后续（P2）
  └─ 健康检查、日志、无障碍、用户指南
```
